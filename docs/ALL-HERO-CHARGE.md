# 全英雄自然充能与原生HUD修复 — 2026-10-23

用户反馈只有源氏、麦克雷的进度会增长。本轮单独处理本机21英雄的
计时充能与原生显示，不把它等同于21英雄完整大招已经实现。

## 原因与修复

1. `NativeChargeEligibility`只有13个英雄，漏了天使、大锤、秩序之光、
   禅雅塔、路霸、查莉娅、卢西奥、D.Va。补为本机原始21英雄；是否有
   MC攻击适配不再决定是否能计时充能。每个实际模型仍必须通过原生
   charge/cost变量、身份、进程创建时间和类型验证。
2. `NativeMeterDisplay`只允许麦克雷，并写死费用1200。法鸡等英雄
   后台数值已经增长，但原生HUD没有收到通知，始终显示0%。现在在
   已有body逻辑线程，通过原来的Set&Notify通知所有已核实的非源氏
   英雄；费用取实际当前英雄的原生变量，不统一改成1200。
3. 源氏继续由原有专用控制器充能，避免第二个计时写入者。保持现有
   5原生点/秒策略、真实伤害信用、整数小数累计、满值上限、身份切换
   清理及已接通大招的施放期暂停策略。本轮没有改变任何英雄费用。
4. HUD通知仍检查当前控制者、模型、HeroInfo、变量包归属、两个变量
   的ID/类型、原始setter代码/虚表及有限数值范围；代码调用仍在原生
   逻辑线程。没有新回调所有者、远程执行线程或替代MC版进度条。

## 实际测试

`tools/verify/verify_native_passive_charge.py`通过真实选人和空闲等待观察原生
变量，保存原始窗口截图。不攻击、不授能、不改时间、不用F11。

修复前`before-v2`：法鸡实际增长29点/5.93秒左右，窗口仍为0%；大锤、
天使、D.Va分别1800/1300/400费用，空闲样本均增长0。初次before因
测试脚本错误使用ResearchProcess上下文管理器未执行观测，保留失败。

点/秒。原始数值及逐帧样本见result.json。21组前后HUD截图合成的
`hud-contact-all21.jpg`已实际查看：20名英雄原生百分比都有增长。

计量现在实际自然增长，但这不能冒充已看见原生百分比，更不能冒充
机甲召回/自爆完整实现。这个既有多形态/UI缺口需要单独记录。
