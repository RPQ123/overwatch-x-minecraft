# 桌面启动器（第一版）

日常双击根目录 ow x mc 启动器.exe。旧Start/Stop/Configure
入口继续保留，均使用当前工程Python和原有独立监督。

首页可启动/继续、正常重启、正常停止、显示两游戏窗口、打开设置、
新建同种子世界和查看日志。世界/画质设置保存后需正常重启生效。
默认1080p、OW Low、8区块、无光影、昼夜循环；F6独立飞行，
F7/F8/F9门户、F10随机怪、F11充满大招，设置拒绝重复占用这些键。

关闭启动器窗口不结束游戏；需要结束会话时使用“正常停止”。
启动或恢复动作交给独立协调进程，游戏由已有监督器保持。
反复点击启动不会新建第二套适配器；重复打开启动器会显示现有窗口。
失败恢复不会直接继续下一步启动，具体日志在 research/launcher/。

状态中的“等待选择英雄”是正常阶段，确认英雄后才进入战斗绑定。
“运行信号已连接”表示监督/绑定信号，不替代实际画面和技能验收。
历史崩溃、陈旧PID、未就绪条件和错误单独显示，退出码0不等于无异常。

Boss地图库当前读取 config/pve-maps.json。五张都是候选，尚未安装或通过
OW融合实战，因此不提供冒称可玩的挑战按钮。完成下载、预检、实际战斗及
重置验证后再启用对应入口。英雄进度页也保留真实未完成项。

## 2026-10-23 设置与操作互斥、错误回执增量（代码通过，待实机）

修复了设置窗口绕过启动器操作互斥的问题。现在启动器的设置按钮，以及
旧 Configure --gui 入口，均通过同一独立协调器打开设置。协调器等待窗口
关闭才释放操作互斥；启动、停止、重启和新建世界不会与该设置窗口并行。
设置子窗口仍使用隐藏 PowerShell/现有 Python，并显式显示自己的 Tk HWND，
避开本机 pythonw 重定向器的多余控制台问题。

关闭并重新打开启动器时，会用操作进程的 PID、创建时间、解释器和脚本路径
确认设置协调器是否仍存活。真实存活才保持按钮忙碌；历史 running 标志或
复用的 PID 不会让 UI 永久锁住。设置打开时需要先保存或关闭该窗口，随后
才能提交启动/停止/重启。关闭主 UI 仍不结束设置或游戏后台。

每次操作附带独立 requestId；进程退出后的提示只读取本次匹配回执。
旧操作的错误不会再冒充本次结果；退出0但缺少本次完成回执也不会显示成功。
设置窗口关闭只表示编辑结束，不宣称已保存。中文子进程日志使用显式 UTF-8。
编辑器保存时附带打开时的配置 SHA256，外部已改配置则拒绝覆盖并提示重开。

本轮46项启动器、9项设置 fixture 通过，含受控 PowerShell Stub 的等待/退出码、

真实窗口、发送游戏输入、安装/重启游戏或修改当前 settings/profile。

打开/关闭、主 UI 关闭重开、中文错误和正常重启组合，不能据 fixture 声称完成D阶段。
