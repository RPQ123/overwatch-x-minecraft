## 7. D阶段：完整桌面启动器 UI

现有 launchers/Configure-Overwatch-Minecraft.cmd 调用的是 Tkinter 设置窗口；
Start/Stop 脚本和独立监督器已经存在。新 UI 复用其经过验证的启动、
恢复、设置和进程身份机制，优先用现有 Python/Tkinter/ttk 做原生桌面入口，
不为外观再引入另一套游戏监督或注入框架。

| 页面 | 用户可直接使用的功能 |
| --- | --- |
| 首页 | 继续游玩、新世界、选择PVE地图、启动、正常重启/停止，显示当前世界和状态 |
| 地图库 | 封面、Boss介绍、作者/来源、版本/依赖、安装状态、兼容结论、开始/重置挑战 |
| 世界 | 当前地图、种子、新建自然世界、导入Java世界、打开MC窗口进行建造 |
| 画面/操作 | 分辨率、区块、OW画质、MC光影、昼夜、粒子、声音、热键冲突检查 |
| 英雄进度 | 每人已验收技能/已知缺口及规则版本，不能把“可选”显示成“已完整” |
| 状态/诊断 | 分步骤进度、可理解的错误、查看日志、导出本地诊断、正常恢复和重试 |

默认种子保留 -490526775015596785；可选新世界而非每次强制新建。
MC窗口可切换、不置顶；默认到有原生英雄动画的选人界面，MC为背景。
已分配F7/F8门户、F9暮色森林门、F10随机怪、F11充满大招；飞行默认F6。
现有设置窗仍允许飞行选F9/F10，需修复这种冲突，不能在新UI继续放行。
工具热键与地图脚本是否冲突纳入对应PVE档案。

必须实现的运行行为：

- 双击、连点或重复打开UI只接管/显示本项目现有会话，不叠加第二套原生模块。
- 关闭UI后独立后台继续；换人、跨维度、攻击和技能不依赖聊天或UI存活。
- UI异步显示启动步骤，不因等待Java或日志而卡死；设置原子保存。
