# Explosions and Minecraft terrain — 2026-10-23

The user requested that implemented explosions can destroy blocks with
different strengths, then explicitly exempted McCree Flashbang and Pharah
Concussive Blast. The latest rule preserves those two control skills' existing
flash/air presentation, damage/status and impulse, but removes their newly
added terrain explosions. All other actual explosions below retain destruction.
This is a custom MC rule, not a claim about destructible Overwatch maps or native
beta metadata. The explicit exemptions supersede the intermediate all-skills
terrain policy.

`NativeExplosionTerrain` owns the separate terrain strengths:

| Actual explosion | MC strength |
| --- | ---: |
| Pharah primary rocket | 2.5 |
| Bastion Tank shell | 2.0 |
| Soldier76 Helix | 1.5 |
| Pharah Barrage rocket | 0.6 |
| McCree flashbang | 0 — explicit user exception; no terrain explosion |
| Pharah Concussive Blast | 0 — explicit user exception; no terrain explosion |
| Tracer Pulse Bomb | 3.0 |
| Other admitted generic explosive projectiles | existing positive MC preference, or 1.0 |

These are explosion strengths, not guaranteed block radii. Actual vanilla
blast resistance, liquid shielding, random blast rays and unbreakable block
rules determine the hole. A weak Barrage rocket may break soft terrain without
being promised to destroy stone. Negative-hardness blocks remain protected. No fire
is added and no unloaded chunk is generated by an explosion.

Original native projectile identity, damage, blast rings, timing and typed
terrain-zero metadata remain unchanged. The MC adapter applies the user rule
only after the existing real collision and damage/cover decisions. In
particular, a grenade cannot first remove a wall and then use that same new
hole to apply its own formerly blocked damage or status effect.

The common projectile route uses one real synchronized `ServerWorld`
explosion, with vanilla entity damage and knockback disabled because existing
native-calibrated damage already ran. Pulse uses `NativeTerrainBurst` after its
own effects. Flashbang and Concussive contain no helper or vanilla explosion
creation call; their telemetry explicitly reports zero terrain work and
`explicit-user-exception`. The helper is silent and does
not add a second particle/sound burst or a second damage/impulse. Its vanilla
block destruction still synchronizes through normal NOTIFY_ALL block/chunk
update packets. The dependency-bytecode fixture checks this actual 1.21.1
packet path, independently from ExplosionS2CPacket presentation.

The dedicated fixture also inspects both exempt runtime classes: no method may
call `NativeTerrainBurst.explode` or `createExplosion`, while Flashbang's real
damage/visible slow/flash and Concussive's real damage/impulse/pressure cue must
remain. Pulse still checks that terrain work follows its original damage and
cover decisions. A zero constant alone is not the exemption mechanism; the
actual terrain call sites were removed.

Deadeye blood/kill particles, sword sweeps, ordinary muzzle flashes and renderer
pressure-wave geometry are not independent explosions and do not create extra
craters. End crystals already execute their actual MC explosion; this change
does not add a second blast to them. Future real explosive hero skills should
use the same policy after their own event admission and effect decisions.
